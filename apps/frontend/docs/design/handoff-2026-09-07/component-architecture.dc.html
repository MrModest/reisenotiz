Component architecture
21 screens, one shared vocabulary. The comps are drawn on your shadcn preset — b1GdgzGvQ, neutral base, orange primary, radius 0.45rem, Inter — so what follows maps each screen element to a shadcn component and each colour to a CSS variable from app.css. Nothing below needs a custom colour.

The seven you actually write
EVERYTHING ELSE IS COMPOSITION
Icon + TypeMark
USED 90+×
Lucide, imported per icon from lucide-react — tree-shaken, never the whole set, never an icon font.
<TypeMark type size?="sm"|"md" tone?="muted"|"accent" />
size sm 16 · md 18 · nav 20 · strokeWidth 2
Icon, label and colour all come from one ITINERARY_TYPES record: { icon: Plane, label: "Flight" }. Detail headers render icon + label from the same record; timeline rows render the icon alone. Adding car rental is one entry, not one component.
SyncBadge
USED 9×
Currently drawn four different ways: header chip, item footer row, sidebar block, inline dot.
status: "synced" | "pending" | "offline" | "conflict"
variant: "chip" | "row" | "dot"
detail?: string
One component, three variants. Status text is derived from the sync store, never passed as a string from a screen.
FactRow / FactList
USED 30+×
Mono label left, mono value right, hairline under. Every detail view is a list of these.
items: Array<{label, value, href?, mono?}>
dense?: boolean
This is what makes seven detail views cheap: each view is a facts array plus at most one bespoke header block.
StatCard
USED 12×
Big number over a mono caption, mobile and desktop, only the number size differs.
value: string | number · caption: string
emphasis?: boolean · size?: "sm" | "md"
Size follows the container via a grid, not a viewport check in the component.
BarChart / SplitBar
USED 3×
Nights per year and the transport mix are the only charts. Plain divs, no charting library.
data: Array<{label, value, highlight?}>
height?: number · orientation: "column" | "stacked"
Percentages are computed in the component from raw values, so the two variants share one data shape.
AddressLink
USED 7×
Underlined address that opens the platform map app; carries the coordinate fallback.
address: string · coords?: [number, number]
label?: string
Builds the geo: / maps: URL in one place — platform sniffing must not live in seven detail screens.
Placeholder
USED 3×
Dashed striped box for photos, tickets, drop targets and empty states.
caption: string · height?: number
interactive?: boolean (drop target)
Also the loading skeleton — same box, animated shimmer off the same stripe.

Base UI variant
WHAT CHANGES VS RADIX
asChild becomes render
Every place a Button or link wraps a React Router <Link> — trip rows, timeline rows, AddressLink — uses render={<Link to=… />} instead of asChild. Affects roughly every navigable row in the comps.
Field is first-class
Base UI ships Field with Label, Description, Error and validity state, so the Field wrapper in the earlier draft collapses into shadcn's Field. Keep zod as the schema source; you may no longer need react-hook-form for the simpler forms.
Popover and Dialog anatomy
Root / Trigger / Portal / Positioner / Popup rather than Radix's Content. Only matters if you deviate from shadcn's wrappers — the Sheet used for the mobile add-item picker is already built on it.
Calendar is unchanged
react-day-picker in both variants. Base UI has no time field, so the time half of the plan fields stays a masked Input.
Variant-independent parts
Card, Badge, Item, Empty, Skeleton, Table and Separator are plain markup — the entire trip table, facts lists and stat grid are identical under Radix or Base UI.
Verify before relying on it
Sidebar is a shadcn composite over Sheet. Confirm it is in the Base UI registry for your version; if it is not, the desktop rail is a Sheet plus a nav list, which is a half-day, not a rewrite.
03
Seven itinerary types, one code path
The trap in this app is a FlightView, FlightForm, StayView, StayForm and so on — fourteen components that drift apart within a month. The comps are deliberately drawn so that they do not need it.
SHARED SHELL
WHAT VARIES PER TYPE
ItemDetailLayout
Header, title block, facts, address, notes, sync badge and action bar are fixed. A type supplies one optional hero node, and there are only three: LegHero (long transfer and city transit — origin/destination rail plus a meta footer), EndpointHero (flight and stay — two columns with a middle measure) and MediaHero (amusement). Food and place have none.
ItemFormLayout
Cancel / title / save header, scroll body, sticky footer with save + delete and the offline note. The body is <Field> children in a grid.
itinerary registry
One module per type exporting { tag, label, schema, toFacts(item), Hero?, fields }. Registered in a map keyed by type. A new type is a new module and one map entry — no screen, router or list change.
TimelineRow
Time column, rule, tag, title, one summary line, unsynced dot. The summary string comes from the registry's toSummary(item), so the row never switches on type.
FORMS
One form engine (react-hook-form or equivalent) driven by the registry's zod schema. Validation, dirty tracking, offline draft persistence and the "saves locally, syncs when online" behaviour are written once and inherited by all seven forms.
04
Adaptive without duplicate screens
AppShell owns the split
The only component that knows about breakpoints. Below 900px it renders <TabBar>, above it renders <SideRail>. Both read the same nav config array, so a new destination is one array entry.
Detail is a route, presented two ways
Mobile pushes /trips/:id/items/:itemId full screen; desktop renders the same route element inside the timeline's right pane. One route, one component, no isMobile branch inside it.
Container queries, not media queries
The detail body sits in a 390px sheet and a 400px pane. Sizing off the container means it is correct in both without either caller passing a variant.
Trip list: rows vs table
The one place the two viewports genuinely differ. Keep a shared useTripList() hook for sorting and grouping, and two thin presentational components over it.
05
Inconsistencies
01 to 04 are now applied to the screens; 06 and 07 are decisions that only exist in code.
01
✓
Three-letter tags are gone: types now read as Lucide icons, with the full type name spelled out in detail headers. Accent colour marks the next item or a selection; every other icon is muted, so no type is privileged.
02
✓
Sync state appeared as chip, row, dot and sidebar block with four different phrasings. Every instance now leads with one status word — SYNCED, PENDING, OFFLINE, CONFLICT — and the detail follows after a middot.
03
✓
Detail action bars now share one geometry and two button sizes; the action set per mode (view: Edit + Calendar, edit: Save + Delete) is fixed in the layout, not per screen.
04
✓
Three date shapes remain by intent — SAT 5 SEP in timelines, 05.09.2026 in inputs, 5 – 16 SEP 2026 for ranges. They become three named, locale-aware formatters; no ad-hoc date strings in components.
05
Timeline rows show one or two times depending on whether the item has an end. Make the time column a component with a fixed width so the rules stay aligned at any content.
06
Nothing in the comps covers empty, loading, error or conflict. Each list and detail needs its state set defined now — Placeholder already gives the visual language for all four.
07
Every interactive element in the comps is a div. Using the shadcn components fixes most of this for free — real buttons, Label/htmlFor wiring, and the preset's outline-ring/50 focus ring. What is still on you: the 44px mobile target and Radix-correct dialogs for the add-item sheet.

07
Reproduction audit
A drawing can promise things code cannot keep. This is the pass over my own comps asking, of every element: can an engineer rebuild this exactly, from tokens, with variable data? Four answers were no — those are fixed in the file. The rest are decisions the drawing physically cannot express, written down here instead of left for someone to guess at 11pm.
Fixed in the drawing
WAS UNBUILDABLE, NOW ISN'T
Charts were drawn with hairline tokens as fills
The "how you moved" bar had one stray hex (#5a5a63) and two segments filled with border / input tokens at 10–15% alpha. Reproducing that faithfully means invisible bars on any other surface. Now the preset's ramp, chart-2 → chart-5, and the inactive year bars are bg-muted — a surface token, not a hairline.
A vertical spine that could not be continuous
Mobile timeline rows carried a 1px rule between the time column and the content: same colour as the row divider, restarting every row, absent on desktop. There is no honest way to build "a continuous thread" out of per-row segments, so an engineer would have had to invent one. Removed — the fixed-width time column carries the rhythm, and both viewports now have identical row anatomy.
One-off spacing to make content fit a crop
The first timeline row was 12px 20px 14px, tuned so the frame filled neatly. Normalised. The Stay form does run a 10px content gap against 12px elsewhere — that one is deliberate density, and it is stated here rather than left to be found by diffing.
Mono caps mislabelled as form labels
81 elements were tagged Label by colour signature. Following that yields a label with no control inside table headers and stat captions. Retagged by role; 61 remain, each with a control after it.
What the drawing cannot show
DECIDED HERE, NOT AT IMPLEMENTATION TIME
The frames are crops, not components
Each screen is a fixed 390×844 or 1440×900 box with overflow:hidden and a 14px bezel. The bezel is not part of the app, and the content is tuned to fill the crop. In the real app all of it scrolls: do not fix heights, do not compress spacing to fit, and expect the Home card and every form to be taller than drawn.
Long strings have no drawn behaviour
"Hotel Weisses Kreuz" fits; a 60-character property name does not. Titles in rows and table cells truncate; detail titles wrap to two lines then truncate; mono meta lines truncate; fact values wrap and never truncate. Every flex child holding text needs min-w-0.
The airport-code route line has no overflow answer
Five or six codes fit; a ten-leg trip does not. Show the first three then +7, with the full chain in trip settings — not a wrap onto three lines.
Fact lists draw a divider under the last row
Because it was easier to draw. In code use ItemGroup separators or last:border-0, or you get a double rule wherever a section follows.
Numbers set in Inter need tabular figures
Stat values and the countdown are Inter. Any number in a column or an animation gets tabular-nums; times and codes are mono and already fixed-width.
Sticky is drawn as static
Timeline day headers, the trip-list search header and every action bar are sticky in the real app; the mock merely places them. Day headers stick under the screen header; action bars stick above the safe area.
22px and 26px bottom paddings are a safe area
Not spacing tokens — that is the home-indicator inset. Use env(safe-area-inset-bottom) with those as the fallback.
